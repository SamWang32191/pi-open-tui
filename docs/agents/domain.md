# Domain docs

This is a single-context repository. Before exploring the code, read the root
`GLOSSARY.md` and any ADRs under `docs/adr/` relevant to the task. If they do
not exist, proceed silently. Create them through `domain-modeling` when a
term or decision is settled, not as empty scaffolding.

Use glossary terms in issues, proposals, and tests. Note real vocabulary
gaps for `domain-modeling`. When a proposal conflicts with an ADR, name the
ADR and explain why the decision is worth revisiting.
